# Survival kit

Keep this next to your laptop — at the office on Monday, or at the [hackathon this Saturday](https://www.aectech.us/nyc-hackathon). Nobody on your team will know you're reading it.

## GitHub in six words you already know

| Word | What it means | In Revit terms |
|---|---|---|
| **Repo** | The project, stored online | The central model |
| **Branch** | Your own copy to work in safely | Your local file |
| **Commit** | Save a version, with a short note | Save local |
| **Pull request** | “Here’s my change. Please review.” | A submittal for review |
| **Merge** | The change joins the project | Sync with central |
| **Pull** | Get everyone else’s latest work | Reload latest |

You won’t type any of these as commands. You’ll ask the agent, in these words.

## The software team phrasebook

| When you hear… | It means… | Tell the agent… |
|---|---|---|
| “Can you push that?” | Upload your saved work | “Commit and push my changes.” |
| “Pull main.” | Get everyone’s latest work | “Pull the latest main into my branch.” |
| “Open a PR.” | Ask the team to review it | “Open a pull request for this.” |
| “Run it locally.” | Start the app yourself | “Start the app. Give me the preview.” |
| “We have a conflict.” | Two edits to the same lines | “Resolve it. Keep both, then explain.” |
| “Put it in .env.” | Keep a secret out of the code | “Where does this key go safely?” |

## The whole skill: ask, look, keep or undo

Look at the preview, not the code. Didn’t work? Say what’s wrong in plain words and go again. Every version is saved, so nothing is more than one sentence away from fixed:

> “Undo your last change and get the app working again.”

New task? Start a new chat. Short conversations stay focused and cost less.

## Dropped into a project you’ve never seen?

| | Tell the agent… |
|---|---|
| **Understand** | “Explain this project like I’m an architect.” |
| **Locate** | “Where would I add [my idea]? Which files?” |
| **Keep it small** | “Make the smallest change that does it. Don’t touch anything else.” |
| **Check** | “Tell me how to check that it works.” |

Works on any team’s code. Nobody has to stop and explain it to you.

## When you’re stuck

1. **Paste the error.** Copy the red text into the agent: “Here’s the error. Find the smallest fix.”
2. **Go back.** “Undo to the last version that worked.” Then ask for something smaller.
3. **Ask a teammate well.** “I’m trying to ___. I expected ___. I got ___.”

Stuck for 10 minutes? Ask a human. On a team, that isn’t weakness. It’s speed.

## Five habits of a great teammate

- **Pull before you start.** Begin every session with everyone’s latest work.
- **Small changes, often.** Three small changes beat one giant one.
- **Stay in your lane.** Work in your own files. Don’t edit a teammate’s.
- **Say what you’re on.** “I’m on the area chart” saves an hour of collisions.
- **Keys stay secret.** Never paste an API key into code or a chat.

## Your first hour on any new project

- [ ] Send your team your GitHub username
- [ ] Open the team’s repo in a Codespace
- [ ] Ask the agent to explain the project
- [ ] Claim a role (problem owner, data finder, tester, demo lead) and one small first task
- [ ] Ship one small pull request on day one

Small and shipped beats big and stuck.

## Demo like a pro in 60 seconds

- **10 s — the annoyance.** One sentence. Who is it painful for, and why?
- **40 s — show it working.** The live app, not the code. One clear path through it.
- **10 s — what’s next.** What you’d build with one more day.

## Your edge

**Don’t start with an app. Start with an annoyance.** Your teammates can code. You know which project problems are worth solving. Bring one to your next team.
